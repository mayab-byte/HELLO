# Design Studio — עורך ויזואלי חי

כלי פיתוח שמאפשר לסגור פינישים ויזואליים בעכבר, בלי סבב פרומפטים,
ולאפות את התוצאה לקוד נקי בבנייה.

---

## שני עולמות שונים לחלוטין

| | פיתוח (`npm run dev`) | פרודקשן (`npm run build`) |
|---|---|---|
| מה רץ | הקוד המקורי **+ פתקים חיים מעליו** | קוד אחד נקי |
| איך מוחל | `<style>` מוזרק עם `!important` | CSS רגיל בקסקדה, **אפס `!important`** |
| טקסטים | מוחלפים ב-innerHTML בזמן ריצה | אפויים לתוך ה-HTML וה-flight payload |
| אלמנט מוסתר | גלוי בעורך, עמום + מקווקו | נמחק פיזית מהתוצר |
| מערכת העורך | נטענת מאחורי `?edit` | **לא קיימת בתוצר** |
| קובץ הפתקים | `studio/overrides.json` | לא עולה |

הקוד המקורי אף פעם לא נוגע. הפתקים חיים בקובץ נפרד, וה-build מקפל אותם לתוצר.

---

## הפעלה

```bash
npm run dev              # Next על 3000 + שרת הסטודיו על 4321
```
פתח `http://localhost:3000/?edit`

בלי `?edit` האתר רץ רגיל — אבל **הפתקים שכבר פורסמו עדיין מוחלים**, כדי שתראה
בזמן פיתוח את מה שסגרת.

## מה הכלי עושה

**בחירה** — hover מסמן, קליק בוחר. קליק על אות בכותרת מפוצלת בוחר את כל הכותרת;
קליק על `<b>` בפסקה בוחר את בלוק הטקסט. חלון "מבנה" (עץ, לקריאה בלבד) פותר
אלמנטים קשים ללחיצה — רקעים, מיכלים, שכבות.

**עיצוב** — טיפוגרפיה (כולל בורר Google Fonts), בורר צבע HSV מלא עם שקיפות,
גרדיאנט על טקסט, צל טקסט, מסגרת ופינות, צל תיבה, מידות, margin ו-padding
ב-4 כיוונים, שקיפות, `mix-blend-mode`, סיבוב והגדלה, עורך רקע מלא
(תמונה + מיקום + גודל + חזרה + שכבת כיסוי), החלפת תמונה.
כל בקרה מספרית = **סליידר + תיבת מספר מסונכרנים**. שדה "מתקדם" (`prop: value`) לכל דבר חריג.

**טקסט** — דאבל-קליק בדף או תיבה בפאנל. `Enter` = פסקה, `Shift+Enter` = שורה,
`⌘B` = בולד. התוכן **משותף לשלושת המסכים**; רק העיצוב נפרד.

**שלושה מסכים** — דסקטופ (≥1025) · טאבלט (768–1024) · מובייל (≤767).
כל מסך בנפרד, בלי ירושה. כפתור "החל על שאר המסכים" מעתיק בלחיצה.

**רשת ביטחון** — Undo/Redo (`⌘Z` / `⌘⇧Z`), "אפס אלמנט", "אפס הכל",
שמירה אוטומטית ל-`localStorage` בכל שינוי (שורדת רענון ו-HMR).

**הסתרה** — נפרדת לכל מסך. בעורך האלמנט נשאר גלוי (עמום + מקווקו) ויש רשימת
"מוסתרים" מרוכזת עם "החזר".

## ארכיטקטורה

```
studio/
  StudioLoader.tsx   גבול ה-client היציב שהלייאאוט מרנדר. אין בו לוגיקה.
  boot.ts            הצומת היחיד שממנו נטענת כל המערכת.
  boot.prod.ts       ← מוחלף לתוכו ב-build לפרודקשן
  Studio.tsx         הפאנל
  useStudio.ts       state, היסטוריה, שמירה אוטומטית
  selector.ts        יצירת סלקטור ייחודי ויציב
  apply.ts           החלה חיה (עם !important)
  picker.ts          כללי בחירה
  color.ts           המרות HSV
  ColorPicker.tsx    בורר הצבע
  controls.tsx       סליידרים ובקרות
  studio.css         UI של העורך (כל המחלקות בקידומת ds-)
  overrides.json     הפתקים

scripts/
  studio-server.mjs  שרת פיתוח: persistence, העלאות, גלריה, פונטים
  bake.mjs           האפייה
  flight.mjs         אפיית ה-RSC flight payload
```

### איך העורך באמת לא מגיע לפרודקשן

שלוש שכבות, מהחלשה לחזקה:
1. `NEXT_PUBLIC_STUDIO=0` → הקוד לא רץ.
2. `import('./boot')` דינמי → לא נטען.
3. **`NormalModuleReplacementPlugin` מחליף את `./boot` ב-`boot.prod.ts`** → כל
   תיקיית `studio/` מנותקת מגרף התלויות ולא נכנסת לתוצר כלל.

השכבה השלישית היא זו שעובדת. בלעדיה Next מפצל את ה-`import()` הדינמי ל-chunk
ומשלח אותו לתוצר גם כשהוא לעולם לא נטען.

**מדוע ההחלפה על `boot` ולא על `StudioLoader`:** החלפת מודול שהוא גבול
`'use client'` שוברת את ה-React Client Manifest והבנייה נכשלת. `boot` הוא
מודול פנימי רגיל, ולכן בטוח להחליפו.

**אימות:** אחרי `npm run build`, חיפוש `ds-panel` / `buildLiveCss` / `Design Studio`
ב-`out/` מחזיר אפס תוצאות.

## האפייה

```
npm run build   =   next build   →   node scripts/bake.mjs
```

| מה | לאן |
|---|---|
| סגנונות | `<style data-studio-baked>` אחרון ב-`<head>`, media query לכל מסך, בלי `!important` |
| טקסט | ה-HTML עצמו **וגם** ה-flight payload |
| מוסתר בכל 3 המסכים | האלמנט נמחק פיזית מה-HTML **וגם** מה-flight payload |
| מוסתר בחלק מהמסכים | `display: none` ב-media query הרלוונטי בלבד |
| פונטים | `<link>` ל-Google Fonts |

קבצי המקור לא משתנים. האפייה חלה רק על `out/`.

### למה ה-flight payload חייב אפייה גם הוא

ב-App Router ה-HTML הוא רק תמונת פתיחה. לצדו יושב `self.__next_f` — תיאור עץ
ה-React שממנו הלקוח מבצע הידרציה. שינוי ה-HTML בלבד לא מספיק: **בהידרציה React
מחזיר את מה שכתוב ב-payload**, כלומר אלמנט שמחקנו יקפוץ בחזרה והטקסט שערכנו
יידרס. `scripts/flight.mjs` מחיל את אותה עריכה על שניהם, לפי חתימה
(`tag` + `id` + `className`) שנגזרת מהאלמנט שכבר אותר ב-DOM. כשההתאמה אינה
חד-משמעית — הסקריפט מדווח ולא נוגע.

## מלכודות שנלקחו בחשבון

1. **`transform` על `<body>` מעגן מחדש כל `position:fixed` צאצא אליו** — ולכן
   שובר את הפאנל ואת ה-overlays. צמצום תצוגת מובייל/טאבלט נעשה ב-`max-width`
   על ילדי ה-body, **בלי `transform`**.
2. **החלה חיה חייבת `!important`** כדי לנצח את ה-CSS הבסיסי — ובפרודקשן הוא נעלם.
3. **פרסום = מיזוג, לא דריסה.** העורך עושה seed מהקובץ המפורסם ושולח סט מלא;
   השרת ממזג לפי סלקטור ומסך. אובייקט ריק = מחיקת ה-override.
4. **סלקטור כללי מדי מתנגש** — כל סלקטור מאומת ב-`querySelectorAll(sel).length === 1`.
5. **מחלקות מעורבלות לא שורדות build** — `selector.ts` מסנן אותן ונופל ל-`:nth-of-type`.
6. **גרדיאנט על טקסט חייב `background-image`** ולא shorthand `background`,
   אחרת `background-clip: text` מתאפס.
7. **בחירה מדלגת על שכבות כבויות** לפי `display`/`visibility` — **לא לפי `opacity`**,
   כי `opacity:0` משמש לאנימציות reveal ואינו אומר "מוסתר".
8. **overlays ממוקמים מחדש ב-scroll וב-resize** עם `getBoundingClientRect` + `position:fixed`.
9. **כותרות מפוצלות-אותיות** — עיצוב בלבד; עריכת נוסח נחסמת כדי לא לשבור את האנימציה.
10. **`trailingSlash` מייצר 308 על `/api/studio/*`** — בפיתוח מבוטל
    (`skipTrailingSlashRedirect`), והשרת סובלני ל-slash מיותר.

## שרת הסטודיו

`http://localhost:4321`, ממופה דרך rewrite ל-`/api/studio/*`. **פיתוח בלבד.**

| נתיב | תפקיד |
|---|---|
| `GET /api/studio/overrides` | קריאת הפתקים |
| `POST /api/studio/publish` | פרסום (מיזוג) |
| `GET /api/studio/images` | גלריית התמונות בפרויקט |
| `POST /api/studio/upload` | העלאת תמונה ל-`public/uploads/` |
| `GET /api/studio/fonts` | רשימת Google Fonts (דורש `GOOGLE_FONTS_API_KEY`, אחרת רשימה מקוצרת) |

בלי מפתח Google Fonts הבורר מציג רשימה מקוצרת עם דגש על פונטים התומכים בעברית.
