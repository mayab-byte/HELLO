# אפיון תשתית אתר תבנית — BMF360

מסמך אפיון לתשתית אתר גנרית, הניתנת לשכפול כפרויקט חדש עבור כל לקוח.

---

## 1. מטרת הפרויקט

בניית **אתר-אב (Boilerplate)** אחד, מלא ותקין, שישמש נקודת מוצא לכל אתר לקוח חדש.
בכל פרויקט: `git clone` → החלפת מיתוג ותוכן → העלאה לאוויר.

| קבוע בין כל הלקוחות | משתנה בכל פרויקט |
|---|---|
| מבנה הקוד וארכיטקטורת הקומפוננטות | צבעים, גופנים, רדיוסים (`app/tokens.css`) |
| מערכת ההרשאות וההתחברות | לוגו, פרטי קשר, טקסטים, תמונות (`content/site.ts`) |
| מערכת הניהול (CMS) | סדר הסקשנים בעמוד הבית |
| שכבת הנגישות | — |
| Design Studio | — |

**אתר הדוגמה**: עסק שירותים כללי — נייטרלי בכוונה.

## 2. פלטפורמה

**Next.js 15 (App Router) + React 19 + TypeScript**, ייצוא סטטי (`output: 'export'`).

| רכיב | בחירה | נימוק |
|---|---|---|
| Framework | Next.js 15, App Router | ייצוא סטטי → תוצר שאפשר לאפות עליו את ה-Studio |
| שפה | TypeScript strict | תופס שגיאות לפני זמן ריצה |
| עיצוב | CSS גלובלי + Custom Properties | **בלי Tailwind ובלי CSS Modules** — ראה למטה |
| שכבת תוכן | `content/site.ts` → בהמשך Postgres + Prisma | אותו מבנה נתונים בדיוק, החלפה נקייה |
| כלי עיצוב | Design Studio (`?edit`) | ראה `docs/DESIGN-STUDIO.md` |

### למה לא Tailwind ולא CSS Modules
ה-Design Studio מזהה אלמנטים לפי סלקטור CSS שחייב **לשרוד את ה-build**.
CSS Modules מייצר מחלקות מעורבלות (`Hero_title__x7Fa2`) ו-Tailwind מייצר שרשראות
מחלקות שמשתנות בכל עריכה — שתיהן שוברות כל סלקטור שנשמר. מחלקות סמנטיות
יציבות (`.hero-title`, `.card-grid`) הן תנאי הכרחי לכלי, לא העדפת סגנון.

### למה לא WordPress
נשקל ונדחה: ל-Design Studio נדרשים שרת פיתוח, שלב build וקבצי מקור בשליטתנו.
בוורדפרס אין build לפרודקשן במובן הזה — התוכן חי במסד נתונים, ו-Elementor
כבר הוא העורך הוויזואלי, בלי הפרדת dev/prod.

## 4. מודל התוכן

בשלב הנוכחי התוכן יושב ב-`content/site.ts` כ-TypeScript מוקלד.
בשלב ה-CMS הוא יוחלף בקריאות למסד — **באותו מבנה בדיוק**, כדי שהקומפוננטות לא ישתנו.

### 4.1 מאמר
כותרת* · תוכן עשיר* · תמונה ראשית* · טקסט חלופי* · תקציר · קטגוריה* · תאריך*

### 4.2 שירות
כותרת* · אייקון · תיאור קצר (לכרטיס)* · תיאור מלא · קישור CTA · סדר תצוגה

### 4.3 פריט גלריה
תמונה* · טקסט חלופי* · כותרת · קטגוריה · סדר תצוגה

### 4.4 המלצה
שם* · תפקיד/חברה · תמונת פרופיל · נוסח* · דירוג 1–5*

### 4.5 הגדרות גלובליות
לוגו · טלפון · מייל · כתובת · שעות פעילות · רשתות חברתיות · פרטי רכז נגישות
עדכון במקום אחד משנה בכל האתר.

> `*` = שדה חובה. **`alt` הוא שדה חובה בכל סוג תוכן עם תמונה** — הלקוח לא יכול לפרסם בלעדיו.

## 5. משתמשים והרשאות

### 5.1 תפקידים
| תפקיד | מי | יכולות |
|---|---|---|
| `admin` | BMF360 | הכל, כולל פתיחת משתמשים |
| `site_editor` | לקוח הקצה | עריכת תוכן בלבד |

**אין הרשמה עצמית.** המנהל בלבד פותח משתמשים ושולח הזמנה במייל.

### 5.2 `site_editor` — כן
עריכת טקסטים ותמונות בעמודים קיימים · יצירה/עריכה/מחיקה של מאמרים, שירותים,
פריטי גלריה והמלצות · העלאה לספריית המדיה · עדכון ההגדרות הגלובליות · צפייה בפניות

### 5.3 `site_editor` — לא
קוד · תוספים · ניהול משתמשים · מבנה עיצובי גלובלי · הוספת/מחיקת עמודים · הגדרות מערכת

### 5.4 התחברות
מסך ממותג בעברית RTL ונגיש · הגבלת ניסיונות (5 → נעילה 15 דק') ·
שחזור סיסמה במייל · סיסמה ≥12 תווים עם אותיות+ספרות+תו מיוחד ·
פקיעת session אחרי 12 שעות חוסר פעילות

### 5.5 אימות דו-שלבי
TOTP (Google Authenticator / Authy) — ללא תלות ב-SMS.
**חובה** ל-`admin`, **ניתן לאכיפה** ל-`site_editor`. קודי גיבוי חד-פעמיים בהפעלה.

## 6. אבטחה

HTTPS בכפייה + HSTS · CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy ·
סיסמאות ב-Argon2id · הגנת CSRF · rate limiting על התחברות ועל הטופס ·
honeypot / reCAPTCHA v3 · גיבוי יומי לשמירה של 30 יום ליעד חיצוני

## 7. נגישות — תקן AA (ת"י 5568 / WCAG 2.1 AA)

הנגישות **מובנית בקוד**, לא תוסף חיצוני.

| נושא | דרישה | מצב |
|---|---|---|
| ניגודיות | 4.5:1 טקסט, 3:1 טקסט גדול ורכיבי ממשק | ✅ בטוקנים |
| מקלדת | כל פעולה נגישה, ללא מלכודות פוקוס | ✅ נבדק |
| Focus | חיווי נראה על כל אלמנט אינטראקטיבי | ✅ |
| מבנה | H1 אחד, היררכיה תקינה | ✅ נבדק |
| Landmarks | header/nav/main/footer סמנטיים | ✅ |
| דילוג לתוכן | ראשון בסדר הטאב | ✅ נבדק |
| תמונות | `alt` בכל תמונה; דקורטיבית `alt=""` | ✅ נבדק |
| טפסים | label לכל שדה, שגיאות מקושרות ב-`aria-describedby`, פוקוס לשדה השגוי | ✅ |
| אנימציה | כיבוד `prefers-reduced-motion` | ✅ |
| שפה | `lang="he"` + `dir="rtl"` | ✅ |
| הגדלה | תקין עד 200% | ✅ |

**תוצאת הביקורת האחרונה:** axe-core (wcag2a/2aa/21a/21aa) — **0 הפרות** בשלושת המסכים.

### הצהרת נגישות
עמוד ייעודי מקושר מהפוטר. פרטי רכז הנגישות נמשכים מההגדרות הגלובליות.

## 9. תשתית טכנית

| נושא | החלטה |
|---|---|
| דומיין | **לא נדרש** — התשתית חיה בפיתוח/סטייג'ינג |
| הרצה | `npm run dev` (Next + שרת הסטודיו) |
| בנייה | `npm run build` = `next build` + `bake` |
| תוצר | `out/` — HTML/CSS/JS סטטי, ניתן לאחסון בכל מקום |
| מייל יוצא | SMTP — **נדרש חשבון** |
| אנליטיקס | הוקים ל-GA4 ו-Meta Pixel, כבויים כברירת מחדל |

### שכפול לפרויקט לקוח חדש
1. `git clone` + `npm install`
2. החלפת `app/tokens.css` — צבעים, גופנים, רדיוסים
3. החלפת `content/site.ts` — שם, לוגו, פרטי קשר, טקסטים
4. החלפת התמונות ב-`public/images/`
5. מילוי פרטי רכז הנגישות
6. `npm run dev -- ?edit` — סגירת פינישים ויזואליים ב-Design Studio
7. `npm run build` + צ'ק-ליסט סעיף 11
