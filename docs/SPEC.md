# אפיון תשתית אתר תבנית — BMF360

מסמך אפיון לתשתית אתר גנרית, הניתנת לשכפול כפרויקט חדש עבור כל לקוח.

---

## 1. מטרת הפרויקט

בניית **אתר-אב (Boilerplate)** אחד, מלא ותקין, שישמש כנקודת מוצא לכל אתר לקוח חדש.
בכל פרויקט חדש: משכפלים את התשתית → מלבישים עליה מיתוג ותוכן של הלקוח → מעלים לאוויר.

מה שאסור להשתנות בין לקוח ללקוח: מבנה הקוד, מערכת ההרשאות, מערכת הניהול, שכבת הנגישות.
מה שמשתנה בכל פרויקט: צבעים, גופנים, לוגו, טקסטים, תמונות, ובמידת הצורך — סדר הסקשנים בעמוד הבית.

**אתר הדוגמה**: עסק שירותים כללי (נייטרלי בכוונה, כדי שיתאים לכל תחום).

---

## 2. פלטפורמה

**WordPress + Elementor**, על גבי Child Theme ייעודי.

| רכיב | בחירה | נימוק |
|---|---|---|
| CMS | WordPress (גרסה יציבה אחרונה) | הלקוח מכיר את הממשק; אקוסיסטם בשל |
| בונה עמודים | Elementor Pro | עריכה ויזואלית, תואם לסקיל `elementor-json` |
| ערכת נושא | Child Theme מותאם (`bmf-base`) | כל הקוד שלנו חי כאן — שורד עדכוני ליבה |
| תוכן דינמי | Custom Post Types + ACF | גלריה, המלצות, שירותים — כל אחד סוג תוכן משלו |
| הרשאות | תפקיד מותאם `site_editor` | ראה סעיף 5 |
| אבטחה | 2FA + Wordfence/מקביל | ראה סעיף 6 |

### למה לא Next.js
נשקל ונדחה: מערכת הניהול שהלקוח מקבל פחות אינטואיטיבית, וזמן ההקמה לכל לקוח ארוך משמעותית. אם בעתיד יידרש אתר עם דרישות ביצועים חריגות — זה מסלול נפרד, לא החלפה של התשתית הזו.

## 4. סוגי תוכן (Custom Post Types)

הלקוח לא בונה עמודים מאפס — הוא ממלא תבניות קיימות. כמו בוורדפרס קלאסי: כותרת, טקסט, תמונה, פרסום.

### 4.1 מאמר (Post — ליבה)
| שדה | סוג | חובה |
|---|---|---|
| כותרת | טקסט | ✓ |
| תוכן | עורך עשיר | ✓ |
| תמונה ראשית | מדיה | ✓ |
| תקציר | טקסט קצר | ✗ |
| קטגוריה | טקסונומיה | ✓ |
| טקסט חלופי לתמונה | טקסט | ✓ (נגישות) |

### 4.2 שירות (`bmf_service`)
כותרת, אייקון/תמונה, תיאור קצר (לכרטיס), תיאור מלא, קישור CTA, סדר תצוגה.

### 4.3 פריט גלריה (`bmf_gallery`)
תמונה, כותרת, קטגוריה, טקסט חלופי (חובה), סדר תצוגה.

### 4.4 המלצה (`bmf_testimonial`)
שם הממליץ, תפקיד/חברה, תמונת פרופיל (אופציונלי), נוסח ההמלצה, דירוג 1-5.

### 4.5 הגדרות גלובליות (עמוד אפשרויות ACF)
לוגו, טלפון, מייל, כתובת, שעות פעילות, קישורי רשתות חברתיות, פרטי רכז נגישות.
כל אלה נמשכים דינמית לכל האתר — עדכון במקום אחד משנה בכל מקום.

## 5. משתמשים והרשאות

### 5.1 מודל המשתמשים
| תפקיד | מי | יכולות |
|---|---|---|
| `administrator` | אנחנו (BMF360) | הכל, כולל פתיחת משתמשים |
| `site_editor` | לקוח הקצה | עריכת תוכן בלבד — ראה להלן |

**אין הרשמה עצמית.** רישום פתוח מושבת ברמת הליבה. המנהל בלבד פותח משתמשים ושולח הזמנה במייל.

### 5.2 מה `site_editor` יכול
✅ לערוך טקסטים ותמונות בעמודים קיימים
✅ ליצור/לערוך/למחוק מאמרים, שירותים, פריטי גלריה, המלצות
✅ להעלות לספריית המדיה
✅ לעדכן את ההגדרות הגלובליות (טלפון, מייל, לוגו, רשתות)
✅ לצפות בפניות מהטופס

### 5.3 מה `site_editor` לא יכול
❌ להתקין/למחוק/לעדכן תוספים או ערכות נושא
❌ לערוך קוד (עורך הקבצים מושבת גלובלית)
❌ לנהל משתמשים
❌ לשנות מבנה עיצובי גלובלי או להוסיף/למחוק עמודים
❌ לגשת להגדרות מערכת

### 5.4 התחברות
- מסך התחברות ממותג, בעברית, RTL, נגיש (לא ברירת המחדל של וורדפרס)
- כתובת התחברות מוסתרת (לא `/wp-admin` הגנרי)
- הגבלת ניסיונות: 5 כשלונות → נעילה ל-15 דקות
- שחזור סיסמה במייל (דורש שירות SMTP — ראה סעיף 9)
- סיסמה: מינימום 12 תווים, אותיות+ספרות+תו מיוחד
- Session פג אחרי 12 שעות חוסר פעילות

### 5.5 אימות דו-שלבי (2FA)
- **חובה** לתפקיד `administrator`
- **מומלץ, ניתן לאכיפה** לתפקיד `site_editor`
- שיטה: TOTP (Google Authenticator / Authy) — ללא תלות ב-SMS
- קודי גיבוי חד-פעמיים בעת ההפעלה

## 6. אבטחה

- HTTPS בכפייה, HSTS
- כותרות אבטחה: CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy
- חסימת XML-RPC ו-REST API למשתמשים לא מאומתים
- הסתרת גרסת WordPress
- השבתת עורך הקבצים (`DISALLOW_FILE_EDIT`)
- הרשאות קבצים: 644 לקבצים, 755 לתיקיות, 600 ל-`wp-config.php`
- גיבוי אוטומטי יומי, שמירה 30 יום, יעד חיצוני
- סריקת קבצים לזיהוי שינויים
- Rate limiting על טופס יצירת קשר + reCAPTCHA v3 או honeypot

## 7. נגישות — תקן AA (ת"י 5568 / WCAG 2.1 AA)

הנגישות **מובנית בתשתית**, לא תוסף חיצוני. תוסף נגישות מסחרי הוא תוספת אופציונלית לכיסוי משפטי, לא תחליף.

### 7.1 דרישות מחייבות בכל רכיב
| נושא | דרישה |
|---|---|
| ניגודיות | 4.5:1 לטקסט רגיל, 3:1 לטקסט גדול (18pt+) ולרכיבי ממשק |
| מקלדת | כל פעולה נגישה במקלדת, ללא מלכודות פוקוס |
| Focus | חיווי פוקוס נראה בבירור על כל אלמנט אינטראקטיבי |
| מבנה | היררכיית כותרות תקינה H1→H6, H1 אחד לעמוד |
| Landmarks | `header`, `nav`, `main`, `aside`, `footer` סמנטיים |
| דילוג | קישור "דלג לתוכן הראשי" ראשון בסדר הטאב |
| תמונות | `alt` חובה בכל תמונה; תמונות דקורטיביות `alt=""` |
| טפסים | `label` לכל שדה, הודעות שגיאה מילוליות וקשורות לשדה |
| כפתורים | שם נגיש ברור; `aria-label` היכן שהטקסט ויזואלי בלבד |
| וידאו | כתוביות בעברית |
| אנימציה | כיבוד `prefers-reduced-motion` |
| שינוי גודל | תקין עד 200% הגדלה ללא אובדן תוכן |
| שפה | `lang="he"` + `dir="rtl"` |
| ARIA | תפריטים, מודלים, אקורדיונים, קרוסלות — עם roles ומצבים תקינים |

### 7.2 מנגנון אכיפה
`alt` מוגדר כשדה חובה בכל CPT עם תמונה — הלקוח לא יכול לפרסם בלעדיו.

### 7.3 בדיקות
axe DevTools + Lighthouse + ניווט מקלדת ידני + קורא מסך (NVDA) לפני מסירה.

### 7.4 הצהרת נגישות
עמוד ייעודי, מקושר מהפוטר. פרטי רכז הנגישות נמשכים מההגדרות הגלובליות ומתמלאים בכל פרויקט לקוח.

## 9. תשתית טכנית

| נושא | החלטה |
|---|---|
| דומיין | **לא נדרש כרגע** — התשתית חיה בסביבת פיתוח/סטייג'ינג |
| אחסון | סביבת פיתוח מקומית (Local/Docker) + סטייג'ינג לצפייה |
| מסד נתונים | MySQL 8 / MariaDB |
| PHP | 8.2+ |
| מייל יוצא | SMTP ייעודי — **נדרש חשבון** (ראה "פתוח") |
| אנליטיקס | הוקים מוכנים ל-GA4 ו-Meta Pixel, כבויים כברירת מחדל |
| טפסים | שמירה במסד + שליחה למייל; הוק מוכן לחיבור CRM |

### שכפול לפרויקט לקוח חדש
1. ייצוא התשתית כחבילה (All-in-One WP Migration / WP-CLI)
2. ייבוא לסביבה חדשה
3. החלפת קובץ `theme.json` / משתני העיצוב — צבעים, גופנים, רדיוסים
4. החלפת לוגו ופרטי קשר בהגדרות הגלובליות
5. החלפת טקסטים ותמונות ה-Placeholder
6. מילוי פרטי רכז נגישות
7. הרצת צ'ק-ליסט הבדיקות (סעיף 11)

**כל המיתוג מרוכז בקובץ משתנים אחד** — זו הנקודה הקריטית שהופכת את השכפול למהיר.

## 10. מסמכים משפטיים

נוסחי בסיס ייכתבו לתשתית, עם שדות להשלמה בכל פרויקט (שם העסק, ח.פ., כתובת, פרטי קשר):

- **מדיניות פרטיות** — לפי חוק הגנת הפרטיות התשמ"א-1981 ותיקון 13 (בתוקף מאוגוסט 2025): איזה מידע נאסף, למה, למי מועבר, זכות עיון ותיקון, פרטי בעל מאגר המידע, מדיניות עוגיות, תקופת שמירה. אם יש קהל באיחוד האירופי — גם סעיפי GDPR.
- **תנאי שימוש** — קניין רוחני, הגבלת אחריות, שיפוט.
- **הצהרת נגישות** — לפי תקנות שוויון זכויות לאנשים עם מוגבלות (התאמות נגישות לשירות): רמת ההתאמה, מועד הביצוע, פרטי רכז הנגישות, דרך לדווח על ליקוי.
- **באנר עוגיות** — עם אפשרות סירוב אמיתית, לא רק "אישור".

> ⚠️ הנוסחים הם תבנית מקצועית, לא ייעוץ משפטי. מומלץ שעו"ד יאשר לפני עלייה לאוויר של לקוח אמיתי.
