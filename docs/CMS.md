# מערכת הניהול

הלקוח נכנס עם אימייל וסיסמה ומנהל את תוכן האתר בעצמו.
עברית RTL, נגישות AA, אפס הפרות axe.

**כתובת:** `/admin` · **מסך התחברות:** `/admin/login`

---

## מה הלקוח יכול

| מסך | מה עושים שם |
|---|---|
| **לוח בקרה** | מבט מהיר: כמה מאמרים, תמונות ופניות שלא טופלו |
| **הגדרות האתר** | שם העסק, טלפון, מייל, כתובת, שעות + הטקסטים של עמוד הבית |
| **מאמרים** | כתיבה, עריכה, טיוטה מול פרסום |
| **שירותים** | הכרטיסים בעמוד הבית, כולל סדר תצוגה |
| **גלריה** | הוספת פריטים מספריית התמונות |
| **המלצות** | שם, תפקיד, נוסח, דירוג |
| **תמונות** | העלאה לספרייה. **טקסט חלופי הוא שדה חובה** |
| **פניות** | מה שהגיע מטופס יצירת הקשר, עם סימון "טופל" |
| **אבטחה** | הפעלת אימות דו-שלבי לחשבון האישי |
| **משתמשים** | *מנהל בלבד* — פתיחת משתמשים, נטרול, שחרור נעילה |

## אבטחה

| | |
|---|---|
| **סיסמאות** | scrypt מ-`node:crypto` בפרמטרי OWASP (N=2¹⁷). בלי תלות מקומית שצריך לקמפל |
| **מדיניות** | 12 תווים לפחות, אות + ספרה + תו מיוחד |
| **הרשמה עצמית** | **סגורה.** משתמש נפתח על ידי מנהל בלבד |
| **הגבלת ניסיונות** | 5 כשלונות → נעילה ל-15 דקות |
| **סשן** | אסימון אקראי בעוגייה `httpOnly`; המסד מחזיק רק את הגיבוב שלו. פקיעה אחרי 12 שעות חוסר פעילות |
| **2FA** | TOTP לפי RFC 6238 — Google Authenticator / Authy / 1Password. חובה למנהל |
| **קודי גיבוי** | 10 קודים חד-פעמיים, מוצגים פעם אחת, נשמרים כגיבוב |
| **טופס האתר** | honeypot + הגבלה של 5 פניות לכתובת IP ב-15 דקות |
| **SVG** | קובץ שמכיל `<script>` או handler מוטבע נדחה בהעלאה |

### שני באגים שנתפסו בבדיקות ותוקנו

**1. הסיסמה חזרה לדפדפן בשלב השני של ההתחברות.**
המימוש הראשון החזיק את הסיסמה בשדה מוסתר כדי לשלוח אותה שוב יחד עם הקוד —
כלומר הסיסמה הייתה חשופה ב-DOM. הוחלף באסימון ביניים חתום ב-HMAC, תקף
5 דקות, שאומר רק "המשתמש הזה כבר עבר את שלב הסיסמה".

**2. שדה הקוד חסם קודי גיבוי.**
השדה הוגדר `pattern="[0-9]*"`, אבל קוד גיבוי מכיל אותיות ומקף. הדפדפן חסם
את השליחה — כלומר בדיוק מי שאיבד את הטלפון לא היה יכול להיכנס.

## מודל הנתונים

Postgres דרך Prisma. `prisma/schema.prisma`.

```
User · BackupCode · Session          משתמשים ואימות
Post · Service · GalleryItem
Testimonial · Media                  תוכן
SiteSettings                         שורה אחת: פרטי העסק וטקסטים
Enquiry                              פניות מהטופס
```

**`Media.alt` הוא `String` ולא `String?`** — טקסט חלופי חסר הוא שגיאת מסד,
לא רק ולידציה בטופס. אי אפשר לשמור תמונה בלי תיאור נגיש.

## התוכן באתר

`lib/site-content.ts` קורא מהמסד, ונופל אחורה ל-`content/site.ts` כשאין נתון.

כך אתר שזה עתה שוכפל נראה מלא עוד לפני שנכנסו למערכת פעם אחת, וכל פריט
שהלקוח מוסיף מחליף את המקביל לו. עמוד הבית מוגדר `dynamic = 'force-dynamic'`,
ולכן שינוי במערכת מופיע באתר מיד.

## הרצה

```bash
# פעם אחת
createdb sitebase
cp .env.example .env          # למלא DATABASE_URL ו-SESSION_SECRET
npx prisma migrate deploy
npm run db:seed               # מנהל ראשון + תוכן התחלה

npm run dev                   # http://localhost:3000/admin
```

`npm run db:seed` בטוח להרצה חוזרת — לא מוחק ולא דורס.
לשליטה בפרטי המנהל:

```bash
ADMIN_EMAIL=me@co.il ADMIN_NAME='שמי' ADMIN_PASSWORD='…' npm run db:seed
```

### משתני סביבה

| משתנה | ל-מה |
|---|---|
| `DATABASE_URL` | חיבור ל-Postgres |
| `SESSION_SECRET` | חתימת אסימון הביניים. **32 תווים לפחות** — `openssl rand -base64 32` |

## פריסה

`npm run build` מייצר אפליקציית שרת. **אין ייצוא סטטי** — מערכת הניהול
קוראת `cookies()` וטופס יצירת הקשר הוא Server Action, ושניהם אינם
נתמכים בייצוא סטטי.

העמודים הציבוריים עדיין מרונדרים מראש ומוגשים מהמטמון, ו-`revalidatePath`
שנקרא בכל פעולת תוכן מרענן אותם מיד — מהירות של אתר סטטי עם תוכן חי.

**לפרודקשן: Vercel + Postgres מנוהל** (Neon או Supabase). שניהם חינם
ברמה שנדרשת לנו, וההגדרה היא שני משתני סביבה.

> ⚠️ **אחסון תמונות.** `lib/media.ts` כותב ל-`public/uploads/` על הדיסק.
> ב-Vercel הדיסק אינו נשמר בין פריסות. לפני שלקוח אמיתי מעלה תמונות יש
> לעבור לאחסון חיצוני; הכתיבה מרוכזת בפונקציה אחת, כך שזה שינוי מקומי.
